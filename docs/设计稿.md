# 言枢 Messages — Windows 10 Mobile 客户端设计稿

> 版本 v1 ｜ 2026-10-11 ｜ 状态：待评审
> 三源合一：**Lumina.Agent** 提供 agent 内核，**Lumina.Roleplay** 提供人设 / 角色卡 / 记忆池体系，**Agents Anywhere** 提供手机 UI 语言。

---

## 0. 一句话结论

做一个**手机优先的原生 UWP 聊天客户端**：手机本地只做「对话 + 工具编排 + 记忆」，模型走用户自配的多 API 档案直连；每个「档案」在工作区里是一个独立文件夹，装着自己的人设、角色卡、世界书、记忆和会话；界面按 Windows 10 Mobile 的单列 Pivot + 时间线语言重做，不再沿用桌面式的 SplitView 三栏。

## 1. 定位与范围

### 1.1 做什么

| 维度 | 决定 |
| --- | --- |
| 形态 | 原生 UWP（C#/XAML），手机优先，桌面可运行以便验证 |
| 目标设备 | Windows 10 Mobile 15254（主），桌面 x86（辅） |
| 模型接入 | 多 API 档案直连（OpenAI 兼容 + Anthropic 原生），不引入自建中转服务 |
| 数据 | 全部落在应用沙箱内的「工作区」，一个档案一个子文件夹 |
| Agent 能力 | 工具循环（19 个工具）、权限批准、子代理、MCP、技能、记忆与 RAG、上下文压缩 |
| 人设能力 | 用户人设、角色卡（SillyTavern v2/v3 导入导出）、世界书、模式注入、好感度 |
| 视觉 | 复刻 Agents Anywhere mobile-v3 的 Win10 Mobile 语言（黑底、直角气泡、时间线轨道） |

### 1.2 不做什么（本轮明确排除）

- **不在手机上跑 Agent 服务端 / Connector**。这是 Agents Anywhere 的模型，与我们要做的事相反：我们是把 Agent 逻辑放在客户端本地，直连模型 API。
- 不移植 Lumina.Agent 的 `EvaluationService` / `LatentChart`（PLAA 论文评测 + 潜变量轨迹图）。它是离线实验工具，与聊天客户端无关，且 `ParseLatentToPoint` 是 hash 占位实现。建议留在原仓库，不进新包。
- 不做浏览器 OAuth、不做远程终端、不做远程文件浏览（那些是 Agents Anywhere 的远端能力）。
- 不引入 WinUI 3 / Windows App SDK。W10M 不支持，必须保持经典 UWP XAML。

### 1.3 三个来源的分工

```
Lumina.Agent  ──►  引擎层（可搬运）
                   工具循环 / 多提供商请求构造 / 流式与 SSE 解析 /
                   记忆抽取 / RAG 检索 / 上下文压缩 / 权限批准 / MCP

Lumina.Roleplay ─► 人设与档案层（可搬运）
                   用户人设 / 角色卡字段与导入导出 / 世界书匹配 /
                   记忆池 + CharacterProfile + 好感度 / 主题令牌体系

Agents Anywhere ─► 界面层（重写，照其语言）
                   时间线行类型 / 单列 Pivot / CommandBar / 窄屏与软键盘处理
```

## 3. 核心概念：档案（Profile）

### 3.1 定义

**档案 = 一个可切换的「人格 + 配置 + 数据」容器**，物理上对应工作区里的一个子文件夹。

它同时承担三件事：

1. **人设**：系统提示词、角色卡字段、首句、示例对话、后置指令（对应 rikkahub 的 Assistant，以及 SillyTavern 的角色卡）。
2. **配置**：用哪个 API 档案 / 哪个模型 / 生成参数 / 开哪些工具与 MCP / 记忆策略 / 外观。
3. **数据**：该档案的会话、记忆池、世界书、知识库文件，彼此隔离。

这样做的直接好处：**换档案 = 换文件夹**，不会串味；**备份 / 迁移 = 打包一个文件夹**；**导入一张角色卡 = 新建一个已经填好的档案**。

### 3.2 与 rikkahub「助手」的对照

| rikkahub 概念 | 本设计 | 差异说明 |
| --- | --- | --- |
| Assistant（助手） | **档案 Profile** | 概念等价，但额外落地为一个文件夹 |
| 系统提示词 | `persona.systemPrompt` | 由角色卡字段自动拼装（见 §8） |
| 模型覆盖 | `api.profileId` + `api.model` | 留空则用全局默认 |
| temperature / topP / maxTokens / reasoningLevel / streamOutput | `api.*` / `generation.*` | 逐项保留 |
| contextMessageSize | `api.contextMessageSize` | 0 = 不限 |
| presetMessages | `generation.presetMessages` | 保留 |
| customHeaders / customBodies | `api.customHeaders` / `api.customBodies` | 保留（中转站需要） |
| mcpServers / localTools / enabledSkills | `tools.mcpServers` / `tools.enabled` / `tools.skills` | 保留 |
| background / backgroundOpacity | `appearance.background` / `appearance.backgroundOpacity` | 角色卡立绘自动作为背景 |
| 记忆（私有 / 全局） | `memory.useGlobal` + 档案私有池 | 保留隔离语义 |
| mode injections / lorebooks | `prompts.injectionIds` / `prompts.lorebookIds` | 保留 |
| 快捷消息、正则转换器 | 快捷消息 P1；正则转换器 P2 | 分期 |
| Tags | `persona.tags` | 保留，用作分组筛选 |

### 3.3 工作区目录布局

工作区根默认为应用 `LocalFolder\workspace`，可在设置里改到 SD 卡 / 文档库（走 `FutureAccessList` 持久授权）。

```
workspace\
├─ _shared\
│   ├─ api-profiles.json          模型档案（全局，可被单个档案覆盖）
│   ├─ global-memory.json         全局记忆池（可选共享）
│   ├─ injections.json            模式注入定义
│   ├─ lorebooks.json             世界书定义
│   └─ quick-messages.json        快捷消息模板
├─ engineering\                   ← 一个档案一个文件夹，文件夹名 = slug
│   ├─ profile.json               人设 + 配置 + 外观（见 §3.4）
│   ├─ card.png                   角色卡原图（保留内嵌 JSON 元数据以便回导）
│   ├─ card.json                  导出的 SillyTavern JSON（spec v2 / v3）
│   ├─ avatar.png                 头像（已降采样 ≤1024px）
│   ├─ memory.json                档案私有记忆池（含向量）
│   ├─ conversations\
│   │   ├─ index.json             会话索引（标题 / 时间 / token / 置顶）
│   │   └─ <convId>.json          单会话（消息 + 分支 + 摘要 + 用量）
│   ├─ files\                     该档案的知识库与附件
│   └─ exports\                   本档案的导出产物
└─ companion\                     另一个档案
    └─ ...（同构）
```

设计要点：

- **`_shared\` 里的东西可以「继承」**：档案没有自己的注入 / 世界书时，默认读共享定义，档案里只存「启用了哪些 id」。
- **`slug` 是文件夹名**，创建后不改（重命名只改 `profile.json` 的 `name`）。冲突时追加 `-2`。
- **删除档案 = 删除文件夹**，但先移入 `workspace\_trash\<时间戳>\` 而不是直接删，避免误触丢数据。
- 会话按档案分目录，而不是塞进一个巨大 JSON。这解决了 `yanshuaiAppData.json` 单文件随对话增长而整体重写的问题。

## 4. 信息架构与导航

### 4.1 导航树

手机屏只有约 360×640 有效像素（mobile-v3 稿就是这个尺寸），所以顶层用**三页根 Pivot**，层级尽量压到两层。

```
启动
 └─ 工作区初始化 / 迁移自检（首次或有待迁移数据时）
     └─ 档案列表（根 Pivot · 第 1 页「对话」）
         │
         ├─[第 1 页 对话]  档案卡片列表 + 会话卡片列表
         │   ├─ 点档案卡片 ──► 档案详情
         │   ├─ 点会话卡片 ──► 会话页
         │   └─ CommandBar：新建会话 / 导入角色卡 / 搜索
         │
         ├─[第 2 页 档案]
         │   └─ 点档案 ──► 档案详情
         │       ├─ 人设（系统提示词 / 字段 / 首句 / 示例）
         │       ├─ 模型与生成参数
         │       ├─ 工具 · MCP · 技能
         │       ├─ 记忆（开关 / 条目管理）
         │       ├─ 世界书 · 注入
         │       ├─ 外观（背景 / 气泡色）
         │       └─ 该档案的会话与文件
         │
         └─[第 3 页 我的]
             ├─ 用户人设（多套，可切换）
             ├─ 模型档案（API 配置列表）
             ├─ 通用设置（主题 / 字体 / 发送键 / 启动行为 / 工作区路径）
             ├─ 数据（导入导出 / 备份）
             └─ 关于 · 调试日志

会话页（第二层，从对话页进入）
 ├─ 时间线（用户消息 / 思考 / 工具 / 最终输出 / 系统 / 错误 / 审批）
 ├─ 顶部栏：返回 · 档案名 · 模型名 · 更多(⋯)
 ├─ 底部 composer：附件行 + 输入框 + 发送/追加/打断
 └─ 更多菜单 ──► 会话设置（重命名 / 归档 / 置顶 / 外观 / 压缩上下文 / 导出这一条）
```

### 4.2 与 Agents Anywhere 导航的差异（为什么改）

Agents Anywhere 是「远端工作区」模型，根 Pivot 是 **会话 / 设备 / 我的**，会话页再套一层 **对话 / 文件 / 终端** Pivot，一共两层 Pivot。我们不需要「设备」这个层级（手机就是本地），也不需要「终端」标签常驻。

保留：根 Pivot 三页、会话页单页（不再套 Pivot，改为「更多菜单 + 二级页面」）。
去掉：设备页、终端页、远端文件浏览。

会话页**不再嵌套 Pivot**——嵌套 Pivot 在手机上会让「左右滑动」产生歧义（滑动到底是切标签还是滚动列表）。文件 / 附件改为从会话页的「⋯」进入二级页。

### 4.3 CommandBar 用法（照源项目，但收紧数量）

源项目的 CommandBar 语义是明确的：会话页对话标签用 `Minimal`（只露 `•••`）、文件标签用 `Compact`（图标带标签）。我们沿用这个语义，但必须注意一条 UWP 的硬约束：

> **UWP CommandBar 的主命令不会自动溢流到「•••」里，超出宽度会被直接裁切。** 溢流只对二级命令（`SecondaryCommands`）生效。

因此在 360 宽（最窄 320）下：

| 位置 | 主命令上限 | 内容 |
| --- | --- | --- |
| 根 Pivot 底部 | 3 | 新建会话 / 导入角色卡 / 搜索 |
| 会话页 | 0（`Minimal`） | 全部走 `•••` 菜单：重命名 / 归档 / 置顶 / 外观 / 压缩上下文 / 导出 / 删除 |

会话页刻意不留常驻图标：一是窄屏放不下，二是这些动作都不是高频动作。**唯一例外是「回到底部」浮动按钮**，它不属于 CommandBar。

### 4.4 草稿会话

新建会话时先建一个「草稿」（不落盘），发出第一条消息时才真正创建。规则：

- 草稿态禁用：附件、追加、打断、命令、设置。
- 草稿态切到别的标签强制弹回对话页。
- 草稿态返回 = 丢弃，不留空会话。
- 真会话创建成功后，草稿的标题与模型选择继承过去。

### 4.5 返回键与生命周期

- `SystemNavigationManager.BackRequested` 统一处理：有叠加面板（审批 / 记忆编辑 / 导入向导）先关面板，其次 `Frame.GoBack()`，最后一层不拦截（让系统挂起应用）。
- **生成中离开会话页不取消请求**。沿用 Lumina.Agent 的做法（`MainPage.Navigation.cs:267-277` 只取消页面级令牌，不取消流令牌），任务经 `AppState.RegisterTask` 持续，回到页面时重新挂接。这是刚需：手机上切出去看别的很常见。
- 挂起（`Suspending`）时先落盘当前会话与记忆池，再 `deferral.Complete()`。
- 崩溃落盘 `LocalState\crash.log`，启动时若存在则提示「上次异常退出」，可复制、可清除。

## 5. 视觉设计系统

### 5.1 取向

照 mobile-v3 的结论：**黑底 + 系统强调色 + 直角 + 单强调色**。移动端信息密度高，不用圆润卡片堆叠，靠「左侧轨道 + 缩进」表达层次，而不是靠一堆圆角容器。

**强调色策略**：默认取系统强调色，并允许「跟随角色卡」——从卡图提取主色作为档案专属强调色（借 Roleplay 的 `Mindscape` 做法：切角色时写 `CustomAccentHex` 并刷新微染画刷）。这是把两个项目的气质接起来的关键一笔。

三个必须照抄的实现细节（源项目已踩过坑）：

1. **三支画刷一起算**：主色 `AccentBrush` = 系统强调色；文字版 `AccentTextBrush` = 主色提亮 55%（`Lighten(accent, 0.55)`）；柔底 `AccentSoftBrush` = 同色 alpha `0x59`。
2. **不要依赖 `AccentLight1/2/3`**：Windows 10 Mobile 上这些系统资源不存在，必须在本地计算浅色阶，否则运行期拿不到值。
3. **不要自己画系统栏**：设计稿里的状态栏与底部导航栏是画板模拟物。真机上由系统提供，我们用 `StatusBar` API 设背景 / 前景色并显示进度指示（仅当 `ApiInformation.IsTypePresent("Windows.UI.ViewManagement.StatusBar")`），没有 StatusBar 的桌面环境退化为页内细进度条。

桌面调试窗口默认给 400×760（源项目的数值），便于在桌面上按接近手机的比例验证布局。

### 5.4 时间线行类型与视觉规则（核心）

这是整个 UI 最需要精确复刻的部分。规则来自 mobile-v3 的「时间线条目怎么区分」表：**除了用户消息，其余一切都不进气泡**，而是走左侧「记忆线 / 步骤轨道」。

| 行类型 | 视觉规则 | 触控行为 |
| --- | --- | --- |
| **用户消息** | 唯一靠右、强调色实心**直角**气泡，右下小三角尾巴；附件行在气泡上方 | 长按：复制 / 编辑 / 删除 / 从这里分支 |
| **思考** | 左侧虚线圆圈（16px，2px dotted accent，旋转动画）+ 斜体灰字；默认折叠 | 点：展开 / 折叠推理全文 |
| **过程步骤组** | 左侧 2px 实心竖轨（`MemoryRailWidth`）+ 步骤节点圆点；**默认只显示最近一步**，上方给「显示前面 N 步」折叠条，折叠条副标题写「思考 4 · 工具 7 · 读取 5 个文件 · 运行 2 条命令」 | 点折叠条展开全部步骤 |
| **工具调用** | 轨道上的方块节点，行内一行标题（工具名 + 参数摘要，等宽字体、`--mid`）；展开后显示结果，长结果折叠 | 点：展开入参 / 出参；出参超 20 行只显示前 20 行 + 「展开全部」 |
| **中间解说** | 缩进的正文块，与最终输出同字号但 `--mid`，左侧 2px `--low` 竖线 | 长按复制 |
| **最终输出** | 无气泡、正常亮色正文；Markdown 全量渲染（标题 / 列表 / 表格 / 代码块 / 引用 / 链接 / 任务列表） | 代码块右上角复制按钮；链接点击 `Launcher.LaunchUriAsync` |
| **系统 / 分隔** | 居中灰字小胶囊（如「已加载 12 条更早消息」「上下文已压缩」） | 点「更早消息」加载历史 |
| **错误** | 左侧红色竖轨 + 红色标题行 + 可展开的详情（堆栈 / HTTP 状态），带「重试」按钮 | 点重试复用原 `clientMessageId` |
| **审批 / 需要你处理** | 会话顶部固定条（不是列表内行），黄色强调条 + 请求标题 + 主操作按钮；点开进入全屏表单 | 见 §6.6 |

**为什么过程走轨道不走气泡**：一张卡里如果出现 7 个工具调用、若干段思考，用气泡呈现会把屏幕刷满，且无法一眼分清「哪条是模型真正说的话」。轨道 + 折叠让「最终输出」成为视觉主角，过程可展开审计。这正是 Agents Anywhere 时间线比 Lumina.Agent 气泡列表更适合手机的地方。

#### 5.4.1 两层数据模型（照抄源项目的分法）

源项目把「行」和「步骤」分成两层，这是轨道能成立的前提，我们沿用：

```
行 RowKind   { User, Process, Output, Marker, Error, Notice }   ← 决定用哪个 DataTemplate
步骤 StepKind{ Reasoning, Tool, Note, Approval, System, Error, More }  ← 轨道内的节点
状态 StepState{ Done, Running, Failed, Stopped }
```

**关键规则：一「轮」里最后一个步骤之前的所有内容，全部并进同一条轨道。**

- 一轮里除了最后一段助手文本，其它助手文本降级成轨道上的 `Note` 步骤（不是独立气泡）。
- 非推理类的 `system` / `error` 事件也降级成轨道上的 `System` / `Error` 步骤。
- **只有最后一段助手文本**成为 `Output` 行。
- 用户消息不参与分组，直接产出 `User` 行。
- 这样长回复天然是「一条轨道 + 一段输出」，而不是十几个气泡。

#### 5.4.2 折叠策略（沿用已验证的常量）

- **运行中且步骤数超过 5 时**，把最早的若干步合并成一个 `More` 节点：标题「显示前面 N 步」、副标题「思考 4 · 工具 7 · 读取 5 个文件 · 运行 2 条命令」，字形 `E712`。常量 `RunningVisibleSteps = 5`——即运行中最多只露最近 5 步，避免边跑边刷屏。
- 单步默认展开条件：该步正在运行，或（失败且是工具步）。其余折叠。
- 整条轨道默认展开条件：正在运行、本轮有失败、或本轮被停止。
- 一步结束、一轮结束都能就地改写这一行的状态，而不是重建整页。

#### 5.4.3 三处必须修掉的源项目缺陷

| 缺陷 | 证据 | 本设计怎么改 |
| --- | --- | --- |
| 审批 / 追问被追加在**时间线末尾** | `TimelineProjection.cs:143-147` 把 notices 一律 append 到 rows 末尾 | 改为**会话顶部常驻固定条** + 会话列表「需要你处理」分组双重提示。长会话里用户不用滚到底才知道有事要处理 |
| 过程轨道会无限长 | 运行中只靠折叠，没有「总数」概念 | 折叠节点固定显示分类计数（见 5.4.2），用户一眼知道一共跑了多少步 |
| 两边渲染能力差得很多 | Agents Anywhere 的 `Ui\TimelineUi.cs` 渲染器**较弱**：不支持图片、嵌套列表、语法高亮，代码块只有纯色。而 Lumina.Agent 的 `Pages\Chat\MarkdownBlock.cs` 反而**更强**，`LatexRenderer.cs` 更是真正的二维盒模型排版 | **不用 Agents Anywhere 的渲染器，直接采用 Lumina.Agent 的 `MarkdownBlock` + `LatexRenderer`**，最终能力超过两个源项目。已知残留：删除线只变灰不真划线、不支持 HTML、代码块内不渲染图片 |

> 另外注意：源项目的 `RowKind`/`StepKind` 是「行=用户可见的一条、步骤=轨道里的一个节点」。做 XAML 时对应两层 `DataTemplate` + 两个 `DataTemplateSelector`，不要试图用一层模板塞下所有形态。

### 5.5 关键组件样式

- **列表行**（设置 / 档案 / 设备）：透明底、`MinHeight 56`、左图标 24px、主标题 15px、副标题 12px `--mid`、右侧 chevron。按下态 `--accent-bg`。
- **卡片**：`--chrome-ml` 底 + 1px `--low` 边 + 12 圆角 + 16 内边距。仅在「档案卡片 / 会话卡片」使用，不在消息流里使用。
- **主按钮**：强调色实心、白字、`MinWidth 96`；**次按钮**：1px 描边透明底；**图标按钮**：48×40 触控区、18px 字形。
- **选中态**：底 `--accent-bg` + 左侧 4px 强调色竖条（mobile-v3 的 `.ses .bar`）。
- **空状态**：84px 圆环（`--accent-bg` 底 + 强调色描边）+ 图标 + 一句 `--mid` 说明 + 一个主按钮。
- **忙碌态**：行内细进度条（非模态），不用转圈遮罩挡整屏。

## 6. 页面设计

每页给出「结构 / 交互 / 状态」三段。

### 6.1 启动与初始化

**结构**：品牌行 + 一根进度条 + 一行状态文字（`--mid`）。
**交互**：顺序执行「加载工作区 → 跑数据迁移（若检测到 `yanshuaiAppData.json` 等旧文件）→ 初始化嵌入引擎（后台，不阻塞）→ 进入根 Pivot」。
**状态**：迁移失败给明确原因 + 「查看调试日志」入口 + 「跳过迁移继续」选项，绝不白屏。沿用 Lumina.Agent 的启动崩溃兜底思路（`App.xaml.cs` 的 `CrashLog` + 友好错误面板），但错误界面要用新设计语言重写。

**迁移**：若发现旧 `yanshuaiAppData.json`，提供一次性导入向导：旧 `ApiProfiles` → `_shared\api-profiles.json`；旧 `Conversations` → 建档为「已导入」档案下的会话；旧图片若还在 `images\` 则迁入档案 `files\`。**迁移只读旧数据，不删除**。

### 6.2 档案列表（根 Pivot 第 1 页）

**结构**：
```
[顶栏] 言枢   [搜索图标] [⋯]
[新建档案 卡片]  ← 虚线边框 + 加号，始终在第一行
[标签筛选条] 全部 | 工程 | 角色 | 翻译 | … （横向滚动）
[档案卡片] × N
   左：48px 圆头像（无头像时用名字首字 + 强调色底）
   中：档案名（15px 半粗）
       副标题：模型名 · 该档案会话数 · 记忆条数
   右：chevron
[分隔] 会话
[会话卡片] × N   标题 / 档案名 / 相对时间 / token 用量 / 置顶标记
```

**交互**：点档案卡片 → 会话列表收窄为「该档案的会话」并就地展开（不跳页，减少层级）；再点一次取消筛选。点会话卡片 → 会话页。

**搜索**：顶栏展开为搜索框，实时过滤档案名 + 会话标题 + 记忆条目（三类结果分组显示）。

### 6.3 新建 / 编辑档案

**结构**：分节表单，节标题用 12px 字距拉开的小标签（`LabelTextStyle`）：
1. **身份** — 名称、头像（拍照 / 相册 / 从卡图）、标签、分组
2. **人设** — 系统提示词（多行，带「插入变量」芯片行）、描述、性格、场景、首句、示例对话、后置指令
3. **模型** — 选择 API 档案（下拉）、模型（下拉 / 手填 + 刷新按钮）、temperature / topP / maxTokens（滑块 + 数字，留空 = 模型默认）、推理等级、上下文条数上限
4. **工具** — 工具开关列表（分「网络 / 文件 / 设备 / 个人 / 代理」五组）、MCP 服务器勾选、技能勾选、FullTrust 开关（带警告文案）
5. **记忆** — 开关、使用全局池、最近会话摘要、时间提醒、自动总结间隔、RAG 开关 + topK + 阈值
6. **外观** — 背景（立绘 / 纯色 / 无）+ 不透明度、用户 / AI 气泡色
7. **模板变量提示** — 底部列出可用占位符：`{{user}}` `{{char}}` `{{cur_date}}` `{{cur_time}}` `{{model_name}}` `{{device_info}}` `{{battery_level}}`，点芯片插入到焦点处。

**交互**：底部固定「保存 / 取消」；有未保存改动时按返回键先确认。**不引入新的 ThemeResource 键**——全部用新项目的令牌集，避免旧项目踩过的「引用了不存在的键，在别的主题下运行期崩溃」。

### 6.4 导入角色卡

**结构**：导入向导三步。
1. **选来源**：PNG 文件 / JSON 文件 / 从 URL（P1）/ 内置卡库（P2）。
2. **预览与补齐**：显示卡图、名称、标签、首句、描述、字段完整度；缺名称时提示填写；缺失字段给「用 AI 补全」按钮（P2，对应 Roleplay 的 `CardCompleter`）。
3. **落盘选项**：档案名、slug（可改）、是否把卡图设为聊天背景、是否导入内嵌世界书、是否创建首会话（含首句）。

**状态与异常**：文件 > 5MB 拒绝并说明；PNG 无 `chara` / `zTXt` 块 → 提示「这不是角色卡，是否当普通图片作为头像」；`zTXt` 解压失败 → 提示具体块名；解析出的字段为 0 条 → 明确提示而不是静默成功（Roleplay 已踩过这个坑）。

### 6.5 会话页（核心页）

**结构**：
```
[顶栏 48px]  ← 返回 |  档案名  ·  模型名  |  ⋯
             （运行中时模型名右侧换成一个 3px 呼吸圆点 + 「运行中」）
[审批固定条]  仅在有 pending notice 时出现（黄条 + 标题 + 主按钮）
[时间线]     ListView（虚拟化）· 行类型见 §5.4 · 顶部可上拉加载更早
             · 底部悬浮「回到底部」小按钮（滚动离开底部 > 1 屏时出现）
[附件行]     仅在有附件时出现：缩略图 × N + 每个右上角小叉
[运行条]     仅生成中可见：20px 进度环 + 状态文字 + 「打断」按钮
             （状态文字如「第 3 步 · 正在执行 write_file」/「等待你批准」/「正在停止…」）
[附件行]     仅在有附件时出现：chip × N（图标 + 名称 + 删除），横向滚动
[composer]   固定底部一行：
             [ 附件 48×40 ] [ 输入框 多行自适应，最高 140px ] [ 发送 或 追加 ]
[软键盘]     依赖 UWP 默认的整页上移（源项目未做任何 InputPane 适配）
```

**发送 / 追加 / 打断**——这个布局沿用 Agents Anywhere 已验证的方案，理由是小屏上比并排三个按钮稳：

| 动作 | 位置 | 语义 | 何时出现 |
| --- | --- | --- | --- |
| 发送 | composer 行末 | 新起一轮，插入用户消息并触发模型 | 空闲态；生成中**隐藏**（同位置被「追加」替换） |
| 追加（steer） | composer 行末，替换发送 | **不打断**当前生成，把这句话塞进模型的下一个上下文窗口 | 生成中；输入框占位符变「追加到当前任务」 |
| 打断（interrupt） | 运行条右侧，常驻 | 停止当前生成，保留已产出部分 | 生成中 |

要点：**发送与追加是同一位置的互斥替换**，不是两个并排按钮——这样输入框可以用满宽度。打断放在输入框上方的运行条里，因此生成中任何时候都点得到，不需要「长按」这种隐藏手势。

**软键盘（必须实测，不能假设）**：Agents Anywhere 全项目没有任何 `InputPane` / `OccludedRect` / `VisibleBounds` 处理，完全靠 UWP 默认行为把页面整体上移。这在「输入框 + 一行按钮」的结构下够用，但源项目已经暴露出三个具体问题，我们要显式处理：

1. 会话内的**全屏表单（审批 / 追问）内容限高 440px**，弹键盘时会被顶出屏幕 → 改为内容区自适应 + 底部按钮固定。
2. **文件编辑页的保存 / 下载在 CommandBar 最底部**，编辑时被键盘挡住，必须先收键盘才能保存 → 编辑态把保存提到顶栏。
3. **终端控制键行夹在输出与输入之间**，键盘弹起后可用的输出高度被压到很小 → 控制键行改为紧贴输入行上方，并在 `InputPane` 显示时滚动到焦点。

**新建会话：先选设置、后建会话（草稿态）**。沿用 Agents Anywhere 的流程：新建时先选档案 / 模型 / 可选标题，得到一个「草稿」会话（不进库、不产生空会话），**发出第一条消息时才真正落盘创建**。好处是避免会话列表里堆一堆空会话，也避免用户选错模型后留下垃圾记录。草稿态下禁用附件 / 追加 / 打断 / 命令，切到别的标签强制回对话页；未发消息就返回则丢弃草稿。

**状态**：空会话显示欢迎面板（档案头像 + 首句已作为第一条助手消息落库）；离线时顶栏显示离线标记，发送按钮禁用并给出原因；额度 / 上下文超限时在输入框上方显示一行黄字警告 + 「压缩上下文」快捷入口。

**流式策略（双通道）**：
- 档案关闭工具 → 走真流式 SSE，逐块渲染，250ms 节流刷新（沿用 `MainPage.Response.cs` 的节流方案）。
- 档案启用工具 → 走工具循环（非流式，因为要拿完整的 `tool_calls`）；**但 UI 不再等到最后才动**：每轮开始时插入一条「思考 / 工具」过程行，工具执行完立即更新该行状态（运行中 → 完成 / 失败），最终输出到达后逐字回放。
- 真流式 + 工具（OpenAI 的 `tool_calls` 增量拼接）列为 P2，不做进首版：收益是过程行能显示模型正在打字，成本是要重写两套 provider 的增量解析。

### 6.6 审批与追问面板

Lumina.Agent 现在是底部滑出面板（`BottomAskPanel` + `AskQuestionsList`），手机上会被软键盘挤压。改为**全屏二级页**：

- **敏感工具批准**：标题「是否允许 写入文件」、说明、参数键值列表（文件名 / 号码 / 路径）、[ 拒绝 ] [ 允许一次 ] [ 始终允许 ]。始终允许写进 `_shared\permissions.json`，可在设置里一键清空。
- **追问（AskUser）**：一次最多 4 个问题，每题 2–4 个选项 + 「其他（自己填）」；支持多选（题末标 `(multi)`）；答完一次性提交。
- **结构化输入（SchemaForm）**：JSON Schema 转原生控件，保留校验，逐字段报错。
- 会话顶部固定条始终显示「有 1 项待你处理」，点进去处理完自动回到会话并滚动到原位。

### 6.7 会话列表

**结构**：按「需要你处理 / 今天 / 更早」分组（沿用 Agents Anywhere 的 `SessionCards` 分组思路），**最上面一组永远是「需要你处理」**，组头用警告色，其余用中性色。

每张卡片是**三行 + 一根左边色条**：

```
▎ 修复手机登录                          10:42
  最后一句：密码派生用 PBKDF2-SHA256…
  ⏱ 需要你处理 · 4.2k tokens
```

| 元素 | 规则 |
| --- | --- |
| 左色条 4px | **需要你处理 → 警告色**；运行中 → 强调色；失败 → 错误色；普通 → 中性色（几乎不可见） |
| 第 1 行 | 会话标题（15px 半粗，省略号）+ 相对时间（今天给 `HH:mm`，昨天给「昨天」，更早给 `M月d日`） |
| 第 2 行 | 最后一句预览（12.5px 次要色，单行省略） |
| 第 3 行 | 状态标签（运行中转圈 / 需要你处理 / 已完成 / 失败）+ token 用量（等宽小字） |

这根色条是列表里唯一的语义信号载体：用户扫一眼就知道哪条要处理、哪条在跑、哪条挂了，不用读文字。

**交互**：点进会话；长按进入多选模式，顶栏变「已选 N 项」，底部出现操作条（归档 / 移动档案 / 删除）。
**空态**：无会话时给圆环空态 + 「新建会话」按钮；搜索无结果时给「换个关键词」提示，两者文案分开，不要混用同一句。

### 6.8 会话设置（二级页）

列表式，一行一个动作，不再把按钮挤在横向一排：

- 重命名（行内编辑）
- 归属档案（可改，改后记忆随之迁移）
- 置顶 / 归档
- 外观（背景 / 气泡色，仅此会话覆盖档案）
- 上下文（当前用量条 `ContextUsageBar` + 「立即压缩」+ 显示已压缩摘要）
- 导出（JSON / JSONL / Markdown）
- 删除（二次确认，移入 `_trash`）

### 6.9 模型与 API 档案

**结构**：列表 + 编辑页。
- 列表：名称（默认项前置 ★）、模型名、连通状态点、长按设为默认 / 复制 / 删除。
- 编辑：名称、提供商类型（OpenAI 兼容 / Anthropic）、URL、Key（写入 `PasswordVault`，不明文落盘）、模型（下拉 + 「刷新模型」调 `/v1/models`）、视觉支持（自动探测 + 手动覆盖）、最大上下文（可覆盖内置表）、自定义请求头 / 请求体（键值对）、副模型（用于记忆总结与 RAG 重排）、「测试连接」按钮。

### 6.10 记忆

**结构**：
- 顶部：开关、模式（私有 / 全局共享）、统计（N 条 / 占用 / 最后更新时间）。
- 列表：每条显示内容、类别标签（偏好 / 事实 / 经历 / 对话）、重要性条、时间、访问次数、来源会话。
- 行内操作：编辑 / 删除 / 提升为全局。
- 右上「+」：手动新增一条（不等模型抽取）。
- 底部：「整理」（合并去重 + 剪枝预览，先给预览再执行）与「清空」（保留导出）。
**交互**：搜索框过滤；按类别 / 重要性排序切换。

### 6.11 世界书与模式注入

**结构**：两个子页，都是「列表 → 详情」。
- 世界书条目：名称、关键词（支持中英标点分隔 / 词边界 / 正则开关 / 大小写开关）、内容、注入位置（系统提示前 / 后 / 对话顶 / 对话底 / 指定深度）、角色（user / assistant）、优先级、常驻开关、启用开关、扫描深度。
- 模式注入：名称、内容、位置、角色、优先级、启用开关。

### 6.12 工具、MCP 与技能

- **工具**：分组开关列表，每个工具带一句人话说明 + 「敏感」标记（需要批准）。`set_working_directory` 在手机上**移除**，改为「档案文件夹即工作目录」；如确需访问外部目录，走「添加授权目录」（`FutureAccessList`）单独入口。
- **MCP 服务器**：名称、类型（http）/ stdio 暂不支持、URL、鉴权头、启用、测试连接、展开查看工具清单。
- **技能**：名称、说明、内容模板、启用；支持从文件导入 / 导出。

### 6.13 文件与附件

- **档案文件**：面包屑 + 列表，行内显示大小 / 修改时间；点击 → 文本预览 / 编辑（UTF-8，带 `ifMatch: sha256` 冲突保护）；图片 → 全屏查看；其他 → 下载。
- **会话附件**：从会话页「⋯」进入；支持从相册 / 文件选择器添加；文本附件进上下文（单文件截断 + 总量上限），图片走视觉通道（模型不支持视觉时明确提示降级为文件名）。
- **限制**（沿用已验证数值）：文本上传 ≤ 4MB、附件单文件 ≤ 25MB、单次 ≤ 10 个、下载 ≤ 25MB 且校验 SHA256。

### 6.14 数据导入导出

- **导出**：单会话（JSON / JSONL / Markdown）、单档案（整个文件夹打包 zip）、全工作区（zip）。
- **导入**：角色卡（PNG / JSON）、旧言枢数据（`yanshuaiAppData.json` / `memory_store.json`）、之前的 zip 备份。
- **覆盖导入必须二次确认**，且采用「先全部反序列化到临时变量、校验通过再提交」的事务式流程（Roleplay 已踩过部分失败导致数据损坏的坑）。
- 导出文件默认落在 `workspace\<slug>\exports\`，可另存到文档库。

### 6.15 关于与调试日志

- 版本、构建号、包族名、设备型号与系统版本。
- 「查看调试日志」：`LocalState\diagnostics.log`，自动轮换，可复制。**记录**：UTC 时间、阶段、HTTP 路径 / 方法 / 状态 / 耗时、WebSocket 状态、异常类型与 HRESULT。**不记录**：API Key、邮箱、Token、请求 / 响应正文、URL query、异常 message。

## 7. 提示词装配管线

系统提示词不再是「一坨字符串」，而是**按注入位置分段的装配管线**，每一段有明确来源与顺序。执行顺序（自上而下拼装）：

```
1. 模式注入（位置 = 系统提示前，按优先级降序）
2. 档案人设
   - persona.systemPrompt（非空则用；为空则按 §7.1 模板拼装）
   - 描述 / 性格 / 场景
   - 后置指令 persona.postHistoryInstructions
3. 用户人设（用户是谁、称呼、偏好）
4. 项目 / 知识库上下文（该档案 files\ 下的注入文件，逐文件截断 + 总量上限）
5. 世界书命中条目（按 Order 排序，过滤 Disable；常驻项无条件注入）
6. 长期记忆（档案池 + 全局池合并，按相关性 + 重要性取前 N）
7. 最近会话摘要（recentChatsReference）
8. 上下文压缩摘要（compressed summary）
9. 工具规则 / 推理规则 / 行为准则（当工具开启时）
10. 时间与环境提醒（cur_date / 设备 / 电量，若开启）
11. 模式注入（位置 = 系统提示后，按优先级降序）
---------- 以下为消息序列内插入 ----------
12. 对话顶注入（首条用户消息之前）
13. 预设消息 presetMessages（对话开头固定示例）
14. 对话底注入（最近一条用户消息之前）
15. 指定深度注入（距末尾 N 条处）
```

**约束**：同一位置、同一角色的多条注入合并为一条消息，结构更干净；**绝不在「带 tool_calls 的助手消息」与其后的 tool 结果之间插入任何内容**——DeepSeek 等 provider 要求这两条相邻，插进去会导致推理链断裂（rikkahub 文档也专门提到这点）。

### 7.1 人设模板（`persona.systemPrompt` 为空时）

```
你是 {{char}}。
[描述] {description}
[性格] {personality}
[场景] {scenario}
[说话风格] 参考示例对话：
{mesExample}
[与用户的关系] {{user}} 是……
```

`mesExample` 为空则省略该节；`description` 等为空则跳过，不留空标题。

## 8. 记忆与 RAG

### 8.1 三层结构（合并旧的三套并行）

| 层 | 作用域 | 落盘 | 内容 |
| --- | --- | --- | --- |
| **会话摘要** | 单个会话 | `conversations\<id>.json` | 上下文压缩产生的结构化摘要（800–1500 字），只服务这个会话 |
| **档案记忆池** | 单个档案，跨会话 | `<slug>\memory.json` | 从多轮对话抽取的离散事实 / 偏好 / 经历，含向量 |
| **全局记忆池** | 全档案（可选） | `_shared\global-memory.json` | 用户身份类事实（名字、时区、长期项目），只有开启 `memory.useGlobal` 的档案可见 |

旧项目的 `MemoryStore` 与 `GlobalMemories` 职责重叠、`Conversation.MemoryItems` 又是第三份。新设计里 `MemoryStore` 的存储与检索代码整体复用，但**只作为「档案记忆池」**；`GlobalMemories` 改为全局池；`Conversation.MemoryItems` 废弃，统一进会话摘要。

### 8.2 条目结构

```
MemoryItem {
  id, summary, embedding[], importance(0–1),
  category("preference"|"fact"|"experience"|"conversation"),
  sourceConversationId, createdAt, accessCount, scope("profile"|"global")
}
```

### 8.3 写入

- 触发：每 N 轮用户消息（默认 10，`minMessagesForSummary`）跑一次抽取。
- 抽取用**副模型**（`api.subModel`，未配置则用主模型），最近 10 条消息进 prompt，输出 `[category] text` 行。
- 重要性映射：`preference 0.8 / fact 0.7 / experience 0.65 / 其他 0.6`；文本 < 3 字丢弃。
- 去重：文本归一化后比对，命中则提重要性 + 更新时间，不新增。
- 写入后立刻把用户消息本身也存一条 `importance 0.5, category=conversation`、截断 500 字（沿用旧行为，但只在 `category=conversation` 上生效，避免污染事实记忆）。

### 8.4 检索

1. 查询改写（P2）：用最近一轮用户输入 + 上一个助手最终输出拼接作为查询。
2. 向量召回：余弦相似度取 `ragTopK × 4` 候选（`ragMinScore` 过滤）——**这两个参数现在真正生效**（旧代码硬编码，见 §2.3）。
3. 融合打分：`score × 0.8 + importance × 0.2`，取前 `ragTopK`，命中项 `accessCount++`。
4. 降级：无嵌入时走 BM25（`K1=1.2, B=0.75`，沿用 `RagMemory.cs` 实现）。
5. 可选重排（P2）：把候选交给模型排序，失败静默降级为本地打分。
6. 注入格式：`【相关记忆】- [类别] 内容（相关度 0.xx）`。

### 8.5 剪枝

- 池上限 `maxMemories`（默认 100，超大档案可调至 500）。
- 满载时按 `importance × 0.7 + 新近度加权` 排序保留 80%：**24 小时内 +0.3，7 天内 +0.15**（保留 Roleplay 的加权思路，数值按本设计重整）。
- 「整理」动作额外清理：`importance ≤ 0.3` 且 30 天未访问的条目；文本重复的合并。
- **任何剪枝先给预览**（将删除 N 条，可逐条取消勾选），再执行。

### 8.6 嵌入来源（分阶段，这是最大的落地风险）

旧项目的现状是：`MemoryStore` 的向量**全部来自云端 `/embeddings`**，本地 `OnEmbedder`（`Lumina.Core\AI\OnEmbedder.cs`，纯 C# SIMD）在 Agent 里从未被调用，而它需要的 `Assets\bge.embmodel` **不在仓库里**（全仓库无此文件，git-lfs 只跟踪了 Roleplay 字体）。

因此分三阶段：

| 阶段 | 方案 | 前提 |
| --- | --- | --- |
| P0（首版即可用） | **BM25 关键词检索** | 无依赖，纯 C#，`RagMemory.cs` 已有实现 |
| P1 | **云端 `/embeddings`** | 用户 API 档案里填了支持 embeddings 的端点；需处理维度变化导致旧向量失配（换模型时提示「重建向量索引」并后台重算） |
| P2 | **本地嵌入** | 用 `OnDeviceAI\model_export\export_model.py` 导出 `bge.embmodel` 并随包携带。**必须先定体积预算**：bge-small-zh 约 33M 参数，fp16 约 65MB、fp32 约 130MB——对 W10M 应用包偏大，需要实测安装与内存占用，或换更小的模型 |

**存储策略**：向量与条目同存 `memory.json`，但用一个独立段（`{ "items": [...], "vectors": { "<id>": [..] } }`），这样重建索引时可以只丢 `vectors` 段而不动文本。

## 12. 构建与部署

沿用 Agents Anywhere 已验证的链路。

```powershell
$msbuild='C:\Program Files (x86)\Microsoft Visual Studio\2017\Community\MSBuild\15.0\Bin\MSBuild.exe'

# 桌面 x86 Debug（日常开发与验证）
& $msbuild Yanshuai.Messages\Yanshuai.Messages.csproj /t:Restore,Build `

# 手机 ARM Release（.NET Native）
& $msbuild Yanshuai.Messages\Yanshuai.Messages.csproj /t:Restore,Build `
  /p:Configuration=Release /p:Platform=ARM /p:VisualStudioVersion=15.0 /v:minimal /nologo
```

签名复用本机现有证书（私钥不可导出，**不要提交私钥、不要改动系统信任设置**）：

```powershell
$cert = Get-ChildItem Cert:\CurrentUser\My |
        Where-Object { $_.Subject -eq 'CN=LockWizard' -and $_.HasPrivateKey } |
        Sort-Object NotAfter -Descending | Select-Object -First 1
$pkg  = 'Yanshuai.Messages\AppPackages\...\*.appx'
& 'C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe' sign /fd SHA256 /sha1 $cert.Thumbprint $pkg
```

部署脚本从 Agents Anywhere 的 `scripts\` 复制改写（`Deploy-Desktop.ps1` / `Launch-Desktop.ps1` / `Deploy-Phone.ps1` / `Launch-Phone.ps1` / `Read-PhoneDiagnostics.ps1`），注意保留这些已经踩过坑的做法：

- 部署前**先关闭本应用进程**再更新（避免 `0x80070005 Access denied`），不要卸载（会丢数据）。
- 脚本绕过系统 HTTP 代理直连设备；用 `curl.exe` 走 multipart（旧 Mobile Portal 不接受 PowerShell `-Form` 生成的 quoted boundary）。
- 同时上传 `Dependencies\ARM` 下的 .NET Native Framework / Runtime。
- 激活接口参数需 UTF-8 base64 再 URL 转义，POST 需 `Content-Length: 0`。
- 读取诊断文件时 Portal 目录 query 用 `%5CLocalState`（缺前导反斜杠会 404）。

### A.2 补充核对结果（值得照抄或必须避开的实现细节）

**值得照抄的四个做法：**

1. **消息列表保持虚拟化**：`ChatItems`（`:409`）用 `ItemsStackPanel`、`CacheLength=1.0`、`IsItemClickEnabled=False`，且**外面不套 `ScrollViewer`**——旧项目注释明确记录过：外套 `ScrollViewer` 会关闭虚拟化并导致内存暴涨。懒加载是「初始 20 条 + 距顶不足 300px 时前插 20 条」。
2. **流式渲染的三层节流**：SSE 后台读取，`await Dispatcher` 提供天然背压；UI 侧 250ms 批量刷新、滚动 200ms 节流；气泡内部再累积 4 个 token 才触发一次 `PropertyChanged`；新增文本用「只追加一个 `Run` + 300ms 淡入」的方式，避免每 token 一次 O(n²) 重排。这套要完整保留。
3. **单气泡操作条**：`_expandedBubble` 保证同一时刻只有一个气泡展开操作条——5 寸屏上是合理设计，保留。
4. **前景色自动对比度**：`R*0.299+G*0.587+B*0.114 > 186 ? 黑 : 白`，避免自定义气泡色后文字看不清。

**必须避开的四个做法（外加两处死代码）：**

1. **思考链挂在气泡上**：旧项目每个助手气泡自带一条「左侧强调色竖条卡片」（`MainPage.xaml:440-528`），思考与工具混排、**默认全部展开**、折叠状态不持久。多个工具调用时每轮都长一条，非常占屏。新设计改为**按轮挂轨道**且默认只露最近一步（见 §5.4）。
2. **审批面板兼职两件事**：`:723 BottomAskPanel` 同时承担 `ask_user` 提问与权限确认，靠改按钮文字区分；且 `AnimatePanelIn` / `AnimatePanelOut` 写了但**从未被调用**（滑入动画是死代码）。新设计把两类拆成各自的全屏页。
3. **子代理定时器漏停**：`DispatcherTimer` 在 `OnNavigatedTo` 启动，却在 `OnNavigatedFrom` **没有停止**。新项目所有定时器必须成对管理。
4. **固定高列表塞长内容**：`RagEntriesList` MaxHeight 240、`LongMemList` MaxHeight 280、`JailbreakPromptBox` 180–320 等，都是写死的。改为自适应。

死代码（不要带入新项目）：`MessageTemplateSelector.cs` 是 4 行空壳（旧项目已改用「单模板 + Visibility 切换」）；`ChatBubble` 里的 `ToolSteps*` / `ReasoningBodyVisibility` 系列属性在 XAML 中**无任何绑定**；`ImportExportPage` 注册为页面但**没有任何 `Frame.Navigate` 入口**（只作静态工具类被调用）；`ChatHistoryPage` 是空壳重定向页。所以「20 个页面」里实际只有约 17 个是活的。
